# ext-port-check

Проверка открытых портов сервера: **изнутри** (`--self`) и **снаружи** по IP или домену.
Один bash-файл, ничего не устанавливает и не меняет на серверах.

Частью проверки для hy2/QUIC служит настоящая QUIC-проба (Version Negotiation, RFC 9000 §6):
UDP-тишина ничего не доказывает, а ответ на неё — доказывает.

## Быстрый старт

```bash
curl -fsSL https://raw.githubusercontent.com/Shepard86rus/ext-port-check/main/ext-port-check.sh -o ext-port-check.sh

bash ext-port-check.sh --self                        # на самом сервере (SSH не нужен)
bash ext-port-check.sh 203.0.113.5                   # снаружи, с другой Linux-машины / WSL
bash ext-port-check.sh 203.0.113.5 vpn.example.com   # несколько целей сразу
```

Требования: Linux или WSL, bash, `timeout`; для `--self` и для режима с SSH — `ss` (iproute2). Конфиг не нужен.

## Два режима — они дополняют друг друга

| Режим | Что показывает | Чего не видит |
|---|---|---|
| `--self` (на сервере) | слушающие порты, живость на loopback (hy2 — QUIC-пробой), лишние публичные порты, свежесть рукопожатий AWG | режет ли порт файрвол или провайдер |
| снаружи (`IP`/домен) | что реально доступно из интернета | что сервер слушает «лишнего» (без SSH) |

Снаружи есть два уровня:
- **без SSH** — стандартные порты: TCP 22/80/443 и UDP 443;
- **с SSH-ключом** (ищется сам в `~/.ssh`, в WSL — и в Windows) — все слушающие порты цели сверяются с белым списком.

## Команды

| Команда | Что делает |
|---|---|
| `--self` | проверка изнутри (этот сервер) |
| `IP [IP ...]` | проверка снаружи; цель — IP, домен или `имя:IP[:пользователь]` |
| `--watch 30` | живой мониторинг: сообщает, когда статус порта изменился |
| `--quiet` | только WARN/FAIL и итог (для cron) |
| `--log ФАЙЛ` | дописывать строку итога в файл |
| `--strict` | WARN тоже считать ошибкой (код возврата 1) |
| `--no-policy` | не сверять публичные порты с белым списком |
| `--ssh-user ИМЯ` | пользователь SSH (по умолчанию `root`) |
| `--help` | справка |

Код возврата: `0` — расхождений нет, `1` — есть FAIL (или WARN при `--strict`), `2` — ошибка запуска.

## Что значат статусы

| Статус | Смысл |
|---|---|
| `OK` | как ожидалось и подтверждено ответом |
| `WARN` | подозрительно: лишний публичный порт, QUIC-проба без ответа |
| `FAIL` | точно неверно: публичный порт недоступен, loopback-порт отвечает снаружи |
| `?` | не подтверждено — UDP без ответа (для AWG это норма: он молчит на посторонние пакеты) |

## Белый список и настройка

По умолчанию публичными считаются TCP 22, 80, 443 + порт sshd цели и UDP 443 + порты AWG цели. Всё остальное, слушающее на `0.0.0.0`, — `WARN` «лишний публичный порт» (частый случай: сервис забыли привязать к loopback).

Необязательный конфиг `~/.ext-port-check.conf` (обычный bash):

```bash
TARGETS=("node1:203.0.113.5" "node2:203.0.113.6")   # тогда запуск без аргументов проверит все
SSH_USER="root"
SSH_KEY="$HOME/.ssh/id_ed25519"
ALLOW_TCP="22 80 443 8443"   # свой белый список TCP
ALLOW_UDP="443"              # свой белый список UDP
```

## Известные ограничения

- AWG снаружи не подтвердить по дизайну (молчит); берётся «последнее рукопожатие клиента» с самой цели — это свидетельство ноды, не снаружи;
- SYN-proxy провайдера может показывать OPEN на мёртвом TCP-порту;
- проверяются только известные порты (из `ss`/`awg`); полный скан — это `nmap`;
- только IPv4; слушатели только на IPv6 помечаются и пропускаются.
